# Prompt Forge 优化清单

> 用途：按批次挑选要做的优化，避免功能越加越散。
>
> - 当前状态：A1 已完成，343 条 UI 断言通过（本地未推送）
> - 工作流：先本地提交；等积累到一批更新后，再统一 `push` / 打 tag / 发新版本
> - 状态标记：`[ ]` 未开始、`[x]` 已完成；进行中保留 `[ ]`，在条目末尾写「（进行中）」

## 推荐优先级

1. **A1 结果就地编辑** —— 日常使用最明显的痛点，改一个词不用再调一次模型。
2. **A2 历史补全与收藏** —— 角色设定目前完全不进历史；顺手补筛选和收藏，成本低。
3. **B1 + B3 接口稳定性** —— 自动重试 + 真实连接测试，减少「偶发失败」和「配置明明对却连不上」。
4. **C1 + C2 保存库资产化** —— 全文搜索、收藏、批量操作、备份导入导出。
5. **D3 + D4 发布工程** —— 单测、CI 跑 UI 回归、版本号、CHANGELOG、截图、图标。

如果只做一批低风险改动：**A2 + A8 + B3 + D4**。  
如果只做一次体验升级：**A1 + A6 + A7 + B1**。  
如果准备下一次 GitHub 发版：**D3 + D4 + C2**，再挑一个功能项。

## A. 结果与工作流

- [x] **A1 · 结果就地编辑** — 价值 高 / 成本 中
  - 现状：结果卡片是只读文本，改一个词也要再发一次微调请求。
  - 做什么：正向、负向、画面解读、参数建议、角色英文/中文、细分标签都可直接编辑；编辑后标记「已手改」；复制、保存、历史使用编辑后的版本；支持一键恢复模型原版。
  - 验收：改完复制/保存内容一致；置顶词不会被重复拼接；刷新前历史和保存库拿到的是编辑版；恢复按钮能回到模型原版。

- [ ] **A2 · 历史补全与收藏** — 价值 高 / 成本 低
  - 现状：角色设定生成后不写历史，历史只有提示词和细分标签两类。
  - 做什么：角色结果入历史并能恢复到角色页；按提示词/角色/细分筛选；条目可收藏并置顶；保留现有搜索和单条删除。
  - 验收：生成角色后历史 +1；点击条目回到角色页并还原英文/中文/画幅；筛选计数正确；收藏状态刷新后还在。

- [ ] **A3 · 多方案生成与对比** — 价值 高 / 成本 高
  - 做什么：一句话一次生成 3 条候选；并排展示标题、正向、负向和解读；选中一条继续微调/保存；支持「再来一批」。
  - 验收：3 条结果互不污染；选中后微调和保存正常；取消时只停当前批次；失败时保留已经成功的候选。

- [ ] **A4 · 导入已有提示词改写** — 价值 中高 / 成本 中
  - 做什么：粘贴一段现成英文 prompt，让模型重构为当前风格、补负面词、给中文解读和参数；支持直接进入微调。
  - 验收：粘贴长 prompt 不丢内容；输出符合当前风格的 JSON 结构；可继续微调、保存和历史。

- [ ] **A5 · 一键生成全部七类标签** — 价值 高 / 成本 中
  - 做什么：细分页增加「生成全部七类」，顺序调用七类并显示进度、当前类型、已用时间；可随时取消；完成后自动加入拼装板。
  - 验收：七类都生成；中途取消不破坏已完成类型；重复类型按拼装板规则替换；失败类型可单独重试。

- [ ] **A6 · 版本时间线与复制格式** — 价值 中 / 成本 中
  - 现状：微调栈只能逐步撤回，无法直接跳到某个旧版本，也没有差异提示。
  - 做什么：把微调栈做成可点选的时间线；任意版本恢复；显示与上一版的差异；复制支持只正向、只负向、JSON、Midjourney 参数等格式。
  - 验收：跳到旧版本后内容与当时一致；差异高亮准确；每种复制格式内容正确；历史同步更新。

- [ ] **A7 · 模板/预设与画幅快捷** — 价值 中 / 成本 低中
  - 做什么：常用题材模板（人像、场景、机甲、国风等）一键填句；负面词预设；自定义目标模型；提示词模式补画幅/镜头/构图快捷选项；可保存自定义预设。
  - 验收：模板能带上风格/画幅等设置；自定义预设刷新后还在；画幅要求能进入提示词或参数建议。

- [ ] **A8 · 草稿自动保存** — 价值 中 / 成本 低
  - 做什么：三个模式的输入、附加要求、当前结果自动保存到本地；刷新或崩溃后恢复；提供「清空草稿」。
  - 验收：刷新页面输入不丢；按模式隔离；清空后不再恢复；不会把 API Key 写进草稿。

## B. 接口与稳定性

- [ ] **B1 · 失败重试与错误分类** — 价值 高 / 成本 中
  - 现状：失败只能手动点重试；没有退避，也没有区分「值得重试」和「重试也没用」。
  - 做什么：429、5xx、超时、网络错误自动退避重试；401/404 直接给配置指引；重试时保留输入和旧结果；显示第几次重试。
  - 验收：模拟 429 后成功，只产生一条历史；401 不自动重试；重试失败后仍能手动重试；不会重复保存。

- [ ] **B2 · 参数可配置与截断提示** — 价值 中高 / 成本 中
  - 现状：`max_tokens` 写死（提示词 2200、角色 2600、细分 1800）；`finish_reason=length` 没处理；思考模型只返回 `reasoning_content` 时界面像卡住。
  - 做什么：设置里可调 `max_tokens`、超时、流式开关、`top_p`、JSON 模式；识别输出被截断并提示；思考模型显示「思考中」；兼容只返回 reasoning 的接口。
  - 验收：调大后长输出不被截断；截断时有明确提示；思考阶段有进度反馈；设置刷新后保持。

- [ ] **B3 · 真实连接测试** — 价值 中 / 成本 低
  - 现状：「测试连接」只请求 `/models`，部分兼容服务不实现这个接口。
  - 做什么：发送一条最小 chat 请求，显示延迟、返回模型名和一句回声；`/models` 不可用时仍能通过测试。
  - 验收：只支持 `/chat/completions` 的服务也能测试成功；Key/BaseURL 错误有明确提示；不产生历史或保存文件。

- [ ] **B4 · 多服务商档案与 Key 安全** — 价值 中 / 成本 中
  - 做什么：保存多套 BaseURL/Key/模型配置，一键切换；Key 可选系统凭据加密（Windows DPAPI / Electron safeStorage）；设置页增加配置校验；支持导出脱敏诊断信息。
  - 验收：两套配置切换后请求走对应地址；Key 不回显；导出的诊断信息不含明文 Key；源码版至少保持现有明文方案并明确提示。

## C. 数据与保存库

- [ ] **C1 · 保存库全文搜索、收藏、批量与排序** — 价值 高 / 成本 中
  - 现状：搜索只覆盖标题、类型、文件名和 110 字摘要；没有收藏、排序和批量操作。
  - 做什么：服务端建轻量全文索引或按需读取全文；收藏置顶；按时间/标题排序；多选删除；搜索结果高亮。
  - 验收：正文后半段的标签也能搜到；收藏刷新后还在；批量删除可撤销；排序切换后列表顺序正确。

- [ ] **C2 · 备份与导入导出** — 价值 高 / 成本 中
  - 做什么：一键导出 JSON 包（saved 文件、元数据、拼装板、历史、脱敏配置）；支持导入合并或覆盖；导入前预览冲突。
  - 验收：导出再导入能完整还原；同名文件有冲突处理；不包含明文 Key；损坏包有错误提示。

- [ ] **C3 · 历史与拼装板落盘** — 价值 中 / 成本 中
  - 现状：历史（上限 60）和拼装板只在 localStorage，换浏览器/清缓存会丢。
  - 做什么：迁移到数据目录的 JSON 文件；首次启动自动迁移旧 localStorage；上限可配置；桌面版和源码版共用同一套 API。
  - 验收：换浏览器/重启后数据还在；旧数据能迁移；文件损坏时能回退到空状态并提示。

- [ ] **C4 · 回收站管理界面** — 价值 中 / 成本 低
  - 现状：删除后只有 8 秒撤销，回收站没有浏览和恢复入口。
  - 做什么：抽屉里查看回收站文件；单条/批量恢复；彻底删除；显示剩余保留天数。
  - 验收：删除后能在回收站看到；恢复后回到保存库；彻底删除后不可恢复；7 天自动清理仍生效。

## D. 界面、无障碍与发布

- [ ] **D1 · 中英双语界面** — 价值 高 / 成本 高
  - 做什么：中/英切换并记住选择；HTML、JS 文案、错误提示、保存库分类、README 截图说明全部覆盖；日期/数字格式跟随语言。
  - 验收：切换后无残留中文；错误提示也翻译；刷新后语言保持；312 条 UI 断言在中英两种语言下都能跑。

- [ ] **D2 · 键盘与无障碍** — 价值 中 / 成本 低
  - 现状：保存库/历史条目是 `div` 点击，键盘无法操作；抽屉没有焦点陷阱；没有快捷键帮助。
  - 做什么：列表项可 Tab + Enter；抽屉焦点陷阱和关闭后焦点归还；增加 `?` 快捷键帮助；流式状态用 aria-live 播报。
  - 验收：只用键盘能打开抽屉、载入、删除、关闭；Esc 行为一致；屏幕阅读器能读到流式进度。

- [ ] **D3 · 测试与 CI 加固** — 价值 高 / 成本 中
  - 现状：CI 只跑静态检查和服务器 smoke，没有跑 UI 回归；服务端函数没有单元测试。
  - 做什么：用 `node:test` 补 `normalizeBaseURL`、配置恢复、保存/重命名/回收站、SSE 解析；CI 安装 Chrome 跑 `npm test`；Windows job 做打包冒烟。
  - 验收：CI 能拦住前端回归；服务端单测覆盖关键路径；打包产物能启动并返回 200。

- [ ] **D4 · 发布工程** — 价值 高 / 成本 低
  - 现状：界面没有版本号；没有 CHANGELOG；截图没覆盖拼装板；exe 没配置自定义图标。
  - 做什么：设置/页脚显示版本号；增加 CHANGELOG；更新截图（含拼装板）；制作 `.ico` 并接入两种打包；发布说明模板化。
  - 验收：界面能看到版本；CHANGELOG 与实际提交一致；exe 图标正确；README 截图是当前界面。

- [ ] **D5 · 桌面版细节** — 价值 中 / 成本 低
  - 现状：`build/electron/main.cjs` 没有单实例锁，重复启动会开多个服务和窗口。
  - 做什么：`requestSingleInstanceLock`，第二次启动聚焦已有窗口；可选托盘/开机启动；记忆窗口大小和位置。
  - 验收：双击两次只保留一个窗口；关闭行为明确；窗口位置刷新后恢复。

- [ ] **D6 · 前端技术债** — 价值 中 / 成本 高
  - 现状：`app.js` 约 3.5k 行，单文件维护；没有 lint/format/type check。
  - 做什么：按 state/api/render/modes/library/board 拆模块；加 ESLint/Prettier 或 oxlint；JSDoc + `tsc --checkJs` 逐步接入。
  - 验收：行为不变、312 条测试全过；lint/type check 进 CI；新增功能不再往单文件堆。

## 不建议现在做

- **云同步 / 账号系统**：和「纯本地、不上传数据」的定位冲突。
- **内置生图 / 模型托管**：成本和定位都变了，容易把工具做重。
- **多用户 / 权限**：本地单用户工具暂时不需要。
- **全量 TypeScript 重写**：收益低、风险高，先用 `checkJs` 逐步补类型即可。
- **Electron 自动更新**：当前是 portable exe，自动更新成本高，先做「检查新版本」链接。

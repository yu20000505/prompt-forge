# Prompt Forge 设定集 MVP 方案

> 状态：本地 MVP 已实现（未发版）  
> 目标版本：2.2（暂定）  
> 更新：2026-10-28

## 0. 已确认的三个决定

1. **生成结果只留在设定集里**，不进入首页通用历史，也不自动进保存库。
2. **设定集内每次生成 1 条提示词**，不做多方案对比。
3. **设定集内部用两个子页签**：`设定` 和 `生成`。

说明：AI 辅助“生成世界方向 / 生成条目候选”属于设定辅助，不属于提示词生成，因此仍保留 3 个候选供选择；提示词生成严格一次 1 条。

---

## 1. 一句话定位

> 设定集是一个独立闭环：先定世界观，再维护人物/物品/生物/地点/势力，最后直接在这个世界里生成提示词并把结果写回条目。

首页的三个生成模式保持不变，不接设定集上下文。

---

## 2. 目标与非目标

### 目标

- 可以创建多个互相独立的世界
- 用 AI 辅助从一句话长出一套世界设定
- 用 AI 辅助生成、扩写具体条目
- 在设定集内部直接生成提示词，自动带上世界规则和选中条目
- 生成结果只属于该设定集，可写回条目的参考提示词
- 数据纯本地，可导出/导入

### 非目标（MVP 不做）

- 关系图谱、时间线、地图
- 图片上传/图库
- 跨世界引用
- 自动生成整本设定集
- AI 自动改写正式设定
- 首页历史/保存库联动
- 多用户协作
- 版本历史（数据结构预留字段）

## 5. 功能清单

### F1 设定集管理

- 新建、打开、重命名、删除
- 搜索
- 多个设定集数据隔离

验收：建 3 个世界，切换后条目和生成记录不串。

### F2 世界核心设定

固定 7 项：

- 世界名
- 类型
- 一句话概念
- 整体基调
- 视觉风格
- 世界规则
- 禁止元素

验收：填完后，生成页能自动带上这些内容。

### F3 五类条目

固定分类：

- 人物
- 物品
- 生物
- 地点
- 势力

通用字段：

- 名称
- 一句话摘要
- 详细设定（字段名 + 内容）
- 视觉锚点
- 禁止项
- 状态：AI 建议 / 正式设定 / 锁定

验收：新增、编辑、删除、按分类筛选。

### F4 AI 生成世界

- 输入 3–5 个种子词
- AI 返回 3 个世界方向
- 选一个方向
- AI 生成 7 项世界核心设定
- 用户逐项确认或修改

验收：2 分钟内从零得到一个可用世界底稿。

### F5 AI 生成条目

- 选分类
- 填一句提示
- 一次生成 3 条候选
- 每条可采纳、编辑后采纳、换一版、丢弃
- AI 结果默认是「AI 建议」，不覆盖已有正式条目

验收：一次生成 3 条候选，采纳后进入正式设定。

### F6 AI 扩写条目

- 扩写当前条目
- 补全缺失字段
- 换一版
- 结果显示为建议，用户确认后保存

验收：AI 不会直接覆盖正式设定。

### F7 设定集内生成提示词

- 当前世界固定
- 可选最多 3 个关联条目
- 6 种生成类型：
  - 自由生成
  - 人物立绘
  - 物品展示
  - 场景概念
  - 生物设定
  - 势力/徽记
- 一次生成 1 条
- 自动带入世界规则、选中条目、视觉锚点、禁止项
- 结果只保存在当前设定集

验收：同一句描述，选不同设定集，结果明显带有对应世界的风格和规则。

### F8 结果写回条目

- 选择目标条目
- 把当前正向/负向/参数写入该条目的 `refPrompt`
- 不修改条目的文字设定

验收：下次生成该条目时，可以手动带入参考提示词。

### F9 导出 / 导入

- 单个设定集导出 JSON
- 导入 JSON
- 不包含 API Key

验收：导出后在另一台机器导入，世界、条目、生成记录完整。

## 6. 生成类型与预填

| 类型 | 需要的条目 | 自动带入 | 用户补充 |
| --- | --- | --- | --- |
| 自由生成 | 可选 | 世界规则、风格、禁止项 | 场景、动作 |
| 人物立绘 | 人物 | 外貌、服装、视觉锚点 | 动作、场景、情绪 |
| 物品展示 | 物品 | 材质、外观、来历 | 摆放环境、镜头 |
| 场景概念 | 地点 | 气候、建筑、氛围 | 时间、人物、事件 |
| 生物设定 | 生物 | 外形、习性、栖息地 | 姿态、环境 |
| 势力/徽记 | 势力 | 理念、结构、徽记、领地 | 载体、构图 |

## 7. 数据结构

每个世界一个 JSON 文件：

```text
DATA_DIR/
  worlds/
    world-xxx.json
```

示例：

```json
{
  "id": "world-xxx",
  "name": "九霄残卷",
  "genre": "东方玄幻",
  "logline": "灵气枯竭后，旧神残卷成为唯一的修行来源",
  "tone": "冷峻、低饱和、宿命感",
  "visual": "青灰、朱砂、旧木、雾气",
  "rules": "禁止现代科技；修行者以寿命换力量",
  "taboos": "现代服装、霓虹、塑料材质",
  "createdAt": 0,
  "updatedAt": 0,
  "entries": [
    {
      "id": "entry-xxx",
      "category": "character",
      "name": "沈照雪",
      "summary": "银发刀客，左眼有旧伤",
      "status": "canon",
      "facts": [
        { "label": "身份", "value": "守夜人末裔" },
        { "label": "外貌", "value": "银发，左眼旧伤" },
        { "label": "服装", "value": "灰白长袍" }
      ],
      "visualAnchors": "银发、灰白长袍、断水刀",
      "taboos": "现代服装、笑容",
      "refPrompt": "",
      "createdAt": 0,
      "updatedAt": 0
    }
  ],
  "generations": [
    {
      "id": "gen-xxx",
      "entryId": "entry-xxx",
      "task": "character",
      "sentence": "雪夜里，她拔刀指向远处的旧神残影",
      "positive": "...",
      "negative": "...",
      "params": {},
      "createdAt": 0
    }
  ]
}
```

约束：

- `generations` 最多保留 50 条
- `entries` 不设硬上限，但列表分页/懒加载
- `refPrompt` 只存提示词文本，不存图片
- 导入时校验 `id` 冲突，自动加后缀

## 8. API 设计

```text
GET    /api/worlds                 设定集列表
POST   /api/worlds                 新建
GET    /api/worlds/:id             世界详情
PUT    /api/worlds/:id             保存世界与条目
DELETE /api/worlds/:id             删除
POST   /api/worlds/import          导入
GET    /api/worlds/:id/export      导出

POST   /api/worlds/:id/ai           AI 辅助（非流式 JSON）
POST   /api/worlds/:id/generate     设定集内生成提示词（SSE）
```

`/api/worlds/:id/ai` 任务：

```json
{ "task": "seed" }
{ "task": "core", "direction": {} }
{ "task": "entry", "category": "character", "hint": "...", "count": 3 }
{ "task": "expand", "entryId": "entry-xxx" }
```

`/api/worlds/:id/generate` 请求：

```json
{
  "sentence": "雪夜里，她拔刀指向远处的旧神残影",
  "entryIds": ["entry-xxx"],
  "task": "character",
  "style": "sd",
  "aspect": "16:9",
  "shot": "wide shot"
}
```

服务端负责读取世界、拼接上下文、调用上游、SSE 返回。

## 9. 世界上下文如何拼接

优先级从高到低：

1. 世界规则与禁止项
2. 选中条目的视觉锚点与禁止项
3. 选中条目的详细设定
4. 世界视觉风格与基调
5. 用户当前一句话

控制：

- 世界核心最多约 800 字
- 每个条目最多约 500 字
- 最多 3 个条目
- 超出时优先保留视觉锚点和禁止项，截断普通描述
- 生成前显示「基于：世界 / 条目」标签

---

## 10. AI 任务提示词原则

- 世界方向：3 个差异明显的方向，不重复
- 世界核心：只输出 JSON，字段固定
- 条目候选：3 条，分类明确，避免和已有条目重名
- 条目扩写：只补缺失，不重写已确认内容
- 所有 AI 结果都带 `status: "suggested"`
- 采纳后才变为 `canon`

## 11. 实施阶段

### 阶段 1：地基

- 世界 JSON 存储与 API
- 设定集列表、世界详情
- 世界核心设定表单
- 五类条目 CRUD
- 导出 / 导入

### 阶段 2：AI 辅助

- AI 世界方向
- AI 世界核心
- AI 条目候选
- AI 单条扩写
- 建议/正式状态与采纳流程

### 阶段 3：生成闭环

- 生成页
- 上下文拼接
- SSE 生成 1 条
- 结果写回条目
- 设定集内生成记录
- 测试与文档

## 12. 验收场景

1. 新建「九霄残卷」，用 AI 生成世界核心，再生成 3 个人物候选，采纳 2 个。
2. 进入生成页，选中「沈照雪」和「断水刀」，生成 1 条提示词；结果出现在当前设定集，不出现在首页历史。
3. 刷新页面后，世界、条目、生成记录都在。
4. 把结果写入「沈照雪」的参考提示词，再次生成时能带入。
5. 导出该设定集，在另一个实例导入，数据完整。
6. 首页三个模式行为不变。

## 13. 风险与应对

| 风险 | 应对 |
| --- | --- |
| AI 生成模板化 | 只生成候选，用户逐条采纳；支持换一版 |
| 用户不想填字段 | 只强制名称/分类/摘要，其余按需展开 |
| 上下文太长、费 token | 世界 + 最多 3 条目，硬上限截断 |
| 设定互相矛盾 | MVP 先做本地缺字段提示，AI 一致性检查放后续 |
| 生成结果找不到 | 生成页固定展示当前世界最近记录 |
| 两套生成 UI 重复 | 共用流式解析、复制、参数格式化，不共用页面 |

---

## 14. 评估点

1. 这个范围是否足够小，能在一次版本里做完？
2. AI 生成条目一次 3 条候选，是否符合你的预期？
3. 生成结果只留设定集、不保存到全局保存库，是否确定？
4. 五类条目是否够用，事件/规则是否要进第一版？
5. 是否需要「锁定」状态，还是先只分「AI 建议 / 正式」？

---

## 15. 一句话总结

> 一个设定集 = 7 项世界底稿 + 五类条目 + 4 个 AI 辅助动作 + 一个只属于该世界的生成页。  
> 首页不变，生成结果不出设定集。
